On the test split both methods recovered all fields for 6/6 clean, 6/6

still common under strong blur. This does not establish a safe error rate.

## Protocol

The cohort contains 12 synthetic originals with four variants each: clean,
mild blur, strong blur, shadow. Six originals (24 variants) are development;
six (24 variants) are test. DejaVu Sans, Serif and Sans Mono are shared
across splits, but document values, field orders, positions and font sizes
differ. Fonts are not held out. The sample is small and variants correlated.
It does not represent real insurance documents, Thai text, handwriting or
captured-photo geometry. Both models are the same installed Tesseract;
the experiment changes image segmentation, not model weights.

Both methods use unchanged enhanced.prepare and extraction_candidate.
The line method segments horizontal ink from pixels, adds margins, enlarges
each crop 2x and uses PSM 7. It never receives expected fields, filenames,
layout labels or reference text during recognition. Upscaling cannot be
assumed to restore destroyed detail.

Development results were recorded first. page_current was selected and the
script, dependencies, manifest and dev report hashes frozen before the
single test run. The fixed comparator was also evaluated. No tuning was
performed after test inspection; this cohort is now consumed and must not
be called an untouched test in future work.

Evidence under experiments/line_cohort_20261016 includes the manifest,
dev/test per-image results, frozen protocol, software and language-data
hashes. Images are deterministically generated by the script and are not
committed. To reproduce image hashes, use the recorded Pillow version and
matching font binaries/hashes. Reports were measured in the assistant's
Linux environment, not the user's Mac/Docker environment.

## Reproduce in a new output directory

    docker run --rm -v "$PWD:/work" insurance-document-orc:pilot python line_ocr_experiment.py generate --dir /work/line_run_01
    docker run --rm -v "$PWD:/work" insurance-document-orc:pilot python line_ocr_experiment.py dev --dir /work/line_run_01
    docker run --rm -v "$PWD:/work" insurance-document-orc:pilot python line_ocr_experiment.py freeze --dir /work/line_run_01 --selected page_current
    docker run --rm -v "$PWD:/work" insurance-document-orc:pilot python line_ocr_experiment.py test --dir /work/line_run_01

These commands reproduce a now-inspected benchmark, not a new untouched
test. Existing directories/reports are protected against overwriting.
CI tests segmentation and protocol guards; it does not run full OCR.

## Next decision

Further simple segmentation/upscaling is not supported by these results.
Evaluate a different recognition model and source-image quality handling on
a new development cohort before proposing a recognition change. Continue
human review/rejection for unresolved numbers. Do not deploy automatic
decimal insertion, digit substitution or benchmark-label lookup.
